# des_split — supervisor and plant on two boards

One ESP32 is the **plant**: it replays the trace of the header, holds the
**private key** and decrypts the decisions. The other is the **supervisor**:
it holds the monolithic supervisor's tables and its encrypted state, with the
**public key only**. The supervisor board never sees the private key, an event
or a decision, and it keeps nothing between steps but the encrypted state.

## How a step hides the event

The supervisor computes the next encrypted state for **every** event (for each
transition q → q' of every event, it sends the cell c[q]); the plant keeps the
cells of the event that occurred, adds a fresh encryption of zero to **every**
cell, and sends the new state back. The supervisor cannot link it to any of
the candidates, so it does not learn which event it was. It then computes the
encrypted decisions — one homomorphic sum per distinct row of R among the
controllable events — and the plant decrypts them with zero tests.

| message | direction | frames per step (2 / 3 clusters) |
|---|---|---|
| `STEP` | plant → supervisor | 1 |
| `CAND` | supervisor → plant: (event, state, cell) per transition | 3 / 39 |
| `NEWST` | plant → supervisor: the re-randomized state | 4 / 30 |
| `DECS` | supervisor → plant: (events, sum) per distinct row | 1 / 1 |

The number of frames, the supervisor's work and the plant's work are the same
for every event: the plant waits for all the candidates, re-randomizes all the
cells (an empty one goes through the same operations on a dummy point) and
tests all the rows. Frames are 1400 bytes, signed with HMAC-SHA256/128 under
the key of `secrets.h`; a lost frame is asked for again (`NACK`).

## Run

1. Copy `des_distributed/secrets.h` into this folder (same Wi-Fi, same key).
2. In `des_split.ino`, pick the header (`supervisor_data_cluster_tool_2.h` or
   `_3.h`, generated by the notebook) and flash one board with
   `#define DES_ROLE DES_PLANT` and the other with `DES_SUPERVISOR`.
3. Open both Serial Monitors, then RESET both boards.

The plant prints, at every step, the decisions next to those of the
supervisor in clear (an oracle a deployment would omit) and the time split
into candidates, re-randomization (of it, drawing the encryptions of zero),
decisions and zero tests; the summary gives the mean with and without the
time spent drawing the encryptions of zero.

## Test on a host

`host_main.cpp` builds either role with g++ (see its header). Without mbedTLS
it uses a mock group with the same algebra and no security, enough to test the
protocol: the 2- and 3-cluster tools pass every step, also with 20 % of the
frames dropped (`-DDES_SIMULATE_LOSS_PCT=20`).
